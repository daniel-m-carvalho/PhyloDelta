# PhyloDelta documentation

PhyloDelta compares two phylogenetic trees side by side in the browser, including trees with
hundreds of thousands of leaves. The browser never downloads a whole tree. The server sends a
summary sized to what the screen can show, and more detail as you navigate.

| Guide | For | What it covers |
|---|---|---|
| [Using the web app](web-app-guide.md) | Anyone comparing trees | Uploading trees, opening a comparison, navigating, searching, view options, isolate data, exporting. Each task has a short video. |
| [Reading a comparison](reading-a-comparison.md) | Anyone looking at the result | What every colour, shape and number on the comparison screen means. |
| [Integrating the API](api-integration.md) | Developers (e.g. PHYLOViZ) | Authentication, the upload → poll → view flow, every endpoint with real examples, errors. |
| [Design record](DECISIONS.md) | Developers, examiners | Why it is built this way: every decision, the alternatives and the measurements. |

The complete, always-current API reference is generated by the server itself at **`/docs`**
(interactive) and **`/openapi.json`** (machine-readable) on any running PhyloDelta instance.

## Running it locally

```bash
cd code/server && uv run phylodelta build-all                          # once: builds the demo data
cd code/server && uv run uvicorn phylodelta.api.app:app --port 8000   # API on :8000
cd code/server && uv run phylodelta worker                             # computes uploads
cd code && npm install && npm start                                    # web app on :5173
```

Or with Docker, from the repository root:

```bash
docker compose up -d --build     # web app on :3001, API on :8001
```

On first start the demo comparisons (vibrio and clostridium) are built automatically.
